The Antigravity history sidebar went blank because modifying `state.vscdb` while the IDE process was active triggered an in-memory state overwrite, or corrupted the JSON schema expected by the UI session index. Non-destructive recovery requires verifying the SQLite backup and bridging persistent NDJSON transcripts from `~/.gemini/antigravity-cli/brain/` back into the database.

## Architectural Strategy

Antigravity IDE stores UI session metadata in an SQLite3 database (`state.vscdb`) within VS Code workspace and global storage directories. When the database is modified externally while Antigravity is running, VS Code's `SQLiteStorageDatabase` service overwrites external changes on shutdown or fails to parse malformed JSON payloads, resetting the sidebar view.

```
┌─────────────────────────────────────────────────────────┐
│              Ground Truth: CLI Brain Logs               │
│          (~/.gemini/antigravity-cli/brain/)             │
└────────────┬──────────────────────────────┬─────────────┘
             │                              │
             ▼                              ▼
┌─────────────────────────┐    ┌─────────────────────────┐
│   Hermes SQLite State   │    │  Antigravity state.vscdb│
│   (~/.hermes/state.db)  │◄──►│  (ItemTable Key-Value)  │
└─────────────────────────┘    └─────────────────────────┘
```

The recovery architecture uses a **fail-safe** three-stage pipeline:
- Freeze and Snapshot: Terminate all running Antigravity IDE and sync processes, then create immutable timestamped snapshots of `state.vscdb`, `state.vscdb.backup`, and WAL journals.
- Integrity Verification: Run SQLite PRAGMA checks on `state.vscdb.backup` to check if previous index keys are intact.
- Transitive Transcript Bridging: If the backup is corrupted or stale, parse ground-truth NDJSON session files in `~/.gemini/antigravity-cli/brain/` and Hermes `~/.hermes/state.db` to reconstruct the `ItemTable` index without losing conversation continuity.

| Storage Layer | Location | Format | Recovery Role |
| :--- | :--- | :--- | :--- |
| Active IDE State | `~/Library/Application Support/Antigravity/.../state.vscdb` | SQLite3 (`ItemTable`) | Target database for UI history display  |
| IDE Backup | `~/Library/Application Support/Antigravity/.../state.vscdb.backup` | SQLite3 (`ItemTable`) | Immediate rollback source  |
| Ground Truth Brain | `~/.gemini/antigravity-cli/brain/<uuid>/` | NDJSON & Markdown | Immutable primary source for reconstruction  |
| Hermes Unified DB | `~/.hermes/state.db` | SQLite3 (FTS5) | Cross-platform metadata and search index |

## Data Structures & State Management

The recovery engine defines structured schema representations to validate and serialize state entries across storage boundaries.

```python
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Any

@dataclass
class SessionSummary:
    session_id: str
    title: str
    created_at: int  # Epoch ms
    updated_at: int  # Epoch ms
    message_count: int
    first_query: str
    model_provider: str
    transcript_path: str
    metadata: Dict[str, Any] = field(default_factory=dict)

@dataclass
class VscdbChatIndex:
    version: int = 1
    entries: Dict[str, Dict[str, Any]] = field(default_factory=dict)

@dataclass
class TrajectorySummaryPayload:
    trajectories: List[Dict[str, Any]] = field(default_factory=list)
    last_active_id: Optional[str] = None
```

The `ItemTable` schema in `state.vscdb` consists of `(key TEXT PRIMARY KEY, value BLOB/TEXT)`. The critical keys governing history sidebar visibility include:
- `antigravityUnifiedStateSync.trajectorySummaries`: Stores trajectory metadata, user goals, and timestamps displayed in the agent panel.
- `chat.ChatSessionStore.index`: VS Code standard chat history registry containing session IDs and label mappings.
- `interactive.sessions`: Workspace-level session mapping containing message identifiers and execution status.

## Logic Flow & Recovery Algorithm

The recovery process proceeds through a strict verification hierarchy.

```
[Start Recovery]
       │
       ▼
[1. Process Lock Check] ──(Running)──► [Terminate Antigravity & Sync Daemons]
       │ (Not Running)
       ▼
[2. Snapshot Current State] ──► Write to ~/.ai-os/recovery/<timestamp>/
       │
       ▼
[3. Inspect state.vscdb.backup]
       │
   ├───┴───────────────────────────────────────────┐
   │ Backup Valid & Contains Sessions              │ Backup Empty / Corrupt
   ▼                                               ▼
[Restore File Directly]               [4. Scan ~/.gemini/.../brain/ & Hermes DB]
   │                                               │
   │                                               ▼
   │                                  [Extract Session Titles & Timestamps]
   │                                               │
   │                                               ▼
   │                                  [Synthesize Trajectory & Index JSON]
   │                                               │
   │                                               ▼
   │                                  [Transactional Write to ItemTable]
   └───┬───────────────────────────────────────────┘
       │
       ▼
[5. Vacuum & Checkpoint SQLite WAL]
       │
       ▼
[6. Verify Keys & Launch Antigravity]
```

### Execution Flow Details
1. Process Verification: Assert no running instance of `Antigravity`, `Electron`, or background thread sync workers hold open SQLite file handles.
2. Cold Snapshotting: Copy `state.vscdb`, `state.vscdb.backup`, `state.vscdb-wal`, and `state.vscdb-shm` into `~/.ai-os/recovery/<timestamp>/`.
3. Backup Assessment: Run `PRAGMA integrity_check;` on `state.vscdb.backup`. Check if keys `antigravityUnifiedStateSync.trajectorySummaries` and `chat.ChatSessionStore.index` exist, are non-empty, and contain valid JSON with session count greater than zero.
4. Transitive Rebuilding (Fallback/Bridge Path): If the backup is blank, iterate through `~/.gemini/antigravity-cli/brain/<uuid>/`. Parse `task.md` or the first user message in `transcript.ndjson` to extract titles, create timestamps, and construct standard trajectory objects.
5. Atomic Transaction: Open `state.vscdb` with SQLite WAL mode, begin an exclusive transaction, insert or update the rebuilt JSON values into `ItemTable`, commit, and execute `PRAGMA wal_checkpoint(TRUNCATE);`.
6. Restart and Sync: Start Antigravity IDE and verify that the sidebar renders all historical threads.

## Execution Steps & Edge Cases

### Edge Cases and Failure Modes
- Database Lock Contention: If Antigravity is open during write operations, SQLite returns `sqlite3.OperationalError: database is locked`. The runner must check for active PIDs and exit before modifying disk files.
- Overwritten Backup File: If Antigravity remained open after the sidebar went blank, it may have mirrored the empty state into `state.vscdb.backup`. The script must inspect entry counts rather than assuming the backup is valid.
- JSON Schema Drift: Antigravity updates may alter expected keys in `ItemTable`. The engine writes both legacy VS Code chat keys (`chat.ChatSessionStore.index`, `interactive.sessions`) and Antigravity-specific keys (`antigravityUnifiedStateSync.trajectorySummaries`) to maintain backward compatibility.
- Character Encoding & Special Chars: Brain transcripts can contain code blocks and null characters that break JSON parsing. Payloads must be sanitized and serialized with `json.dumps(..., ensure_ascii=False)`.

### Ordered Implementation Steps
1. Create Recovery Script `scripts/restore_antigravity_state.py`: Implement `AntigravityStateInspector`, `BrainTranscriptParser`, and `VscdbRecoveryEngine` with CLI flags (`--dry-run`, `--verify-backup`, `--rebuild-from-brain`).
2. Update Transcript Synchronization `scripts/sync_threads.py`: Add an automatic pre-write integrity check that refuses to sync into `state.vscdb` if Antigravity's process lock is detected.
3. Enhance Title Extraction `scripts/extract_antigravity_titles.py`: Ensure trajectory title fallbacks read from `task.md`, `walkthrough.md`, or the initial `USER_INPUT` event in `transcript.ndjson`.
4. Register Verification Command in `bin/ai-os`: Add `ai-os recover-history` subcommand to provide a single non-destructive command for developers encountering blank sidebars.
5. Create Integration Test `tests/test_state_recovery.py`: Mock corrupted `state.vscdb` files and verify that the restoration script recovers session indices without data loss.
