Direct UNIX symlinks are intentionally prohibited by the system architecture because individual agent CLIs atomically overwrite and unlink target paths during updates. Instead, synchronization is managed through an event-driven multi-way synchronization engine (`sync_skills.py` driven by `watch_skills.sh`) that acts as a live virtual link across all platforms, backed by an automated canary verification test.

## Architectural Strategy and Invariants

Raw filesystem symlinks fail across heterogeneous AI environments because tools like Claude Code, Hermes, Antigravity (`agy`), and Gemini frequently perform atomic file writes (`write-temp -> rename -> overwrite`). This pattern replaces symbolic links with concrete files or creates broken pointers when directory trees shift.

```
       ┌────────────────────────────────────────────────────────┐
       │             fswatch Multi-Directory Monitor            │
       └──────┬──────────────┬──────────────┬─────────────┬─────┘
              │              │              │             │
              ▼              ▼              ▼             ▼
      ~/projects/ai-os   ~/.claude      ~/.hermes     ~/.gemini
          /skills/        /skills/       /skills/   /config/skills/
              ▲              ▲              ▲             ▲
              └──────────────┴──────┬───────┴─────────────┘
                                    │
                     sync_skills.py (SHA-256 Mesh)
```

The system implements an event-driven mesh topology where `~/projects/ai-os/skills/` acts as the canonical git repository root alongside peer directories (`~/.hermes/skills`, `~/.claude/skills`, `~/.gemini/config/skills`, `~/.agents/skills`, `~/.agy/skills`). The `sync_skills.py` script computes content hashes, prevents recursive loopbacks via transactional locks, and propagates file creations, mutations, and deletions across all platform directories.

| Platform Path | Primary Harness | Sync Modality | Conflict Resolution |
| :--- | :--- | :--- | :--- |
| `~/projects/ai-os/skills/` | Repository Root (Git) | Source of Truth | Repo Anchor Override |
| `~/.claude/skills/` | Claude Code CLI | Bi-directional Mesh | Latest mtime + SHA-256 |
| `~/.hermes/skills/` | Hermes Agent & WebUI | Bi-directional Mesh | Latest mtime + SHA-256 |
| `~/.gemini/config/skills/` | Antigravity / Gemini Shell | Bi-directional Mesh | Latest mtime + SHA-256 |
| `~/.agents/skills/` | Local Agent Runtime | Bi-directional Mesh | Latest mtime + SHA-256 |
| `~/.agy/skills/` | Local CLI Daemon | Bi-directional Mesh | Latest mtime + SHA-256 |

## State Management and Data Structures

The synchronization engine maintains state in `~/.ai-os/skills_sync_state.json` to track file digests, timestamps, and active sync operations.

```json
{
  "version": 1,
  "last_global_sync": "2026-08-19T16:08:00Z",
  "lock_file": "/tmp/ai_os_skills_sync.lock",
  "watched_roots": [
    "/Users/matt/projects/ai-os/skills",
    "/Users/matt/.claude/skills",
    "/Users/matt/.hermes/skills",
    "/Users/matt/.gemini/config/skills",
    "/Users/matt/.agents/skills",
    "/Users/matt/.agy/skills"
  ],
  "file_registry": {
    "search-clipboard.md": {
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "mtime_ns": 1724083680000000000,
      "origin": "/Users/matt/projects/ai-os/skills/search-clipboard.md"
    }
  }
}
```

State changes occur only when a file content hash changes or when an entry is unlinked, preventing cascade loops when updating timestamps.

## API and Interface Contracts

The synchronization components expose strict CLI interfaces and Python classes for orchestrating changes and handling background daemon notifications.

```python
from pathlib import Path
from typing import Dict, List, Optional

class SkillRecord:
    name: str
    relative_path: Path
    sha256: str
    mtime_ns: int

class SyncEngine:
    state_file: Path
    watched_dirs: List[Path]
    lock_path: Path
    
    def __init__(self, config_path: Optional[Path] = None) -> None: ...
    def scan_directory(self, target_dir: Path) -> Dict[str, SkillRecord]: ...
    def compute_sha256(self, file_path: Path) -> str: ...
    def acquire_lock(self, timeout_sec: float = 5.0) -> bool: ...
    def release_lock(self) -> None: ...
    def sync_file(self, source_path: Path, changed_event: str) -> bool: ...
    def reconcile_all(self) -> Dict[str, List[str]]: ...
```

CLI entry point contracts for orchestrator execution:
- `python3 scripts/sync_skills.py --reconcile`: Full state synchronization pass across all configured directories.
- `python3 scripts/sync_skills.py --sync-file <path> --event <created|modified|deleted>`: Granular single-file update invoked by the filesystem watcher.
- `python3 scripts/sync_skills.py --test-canary`: Automated verification routine that creates, mutates, and deletes a test skill while verifying propagation across all ecosystem paths.

## Logic Flow and Algorithms

Execution flow splits into daemon-driven event processing and full reconciliation passes.

```
[File Event Detected (fswatch)]
               │
               ▼
   [Acquire /tmp Lockfile]
               │
      ├── [Locked?] ──> Debounce and retry
      │
      ▼
   [Extract Relative Skill Path]
               │
      ├── [Event == 'deleted']
      │        │
      │        ▼
      │   Remove matching relative paths across all peer dirs
      │   Update skills_sync_state.json
      │
      └── [Event in ('created', 'modified')]
               │
               ▼
          Compute SHA-256 of modified file
               │
          ├── [SHA Matches State?] ──> Skip (Loopback Suppression)
          │
          └── [SHA Differs]
                   │
                   ▼
              Atomically write payload to all peer targets (write temp -> os.replace)
              Update skills_sync_state.json with new digest
               │
               ▼
   [Release Lockfile & Log Transaction]
```

To eliminate race conditions, file writing uses temporary file creation with atomic replacement (`os.replace`) so partial writes cannot be read by concurrent agent processes.

## Verification Test and Implementation Plan

### Edge Cases and Mitigations
- Incomplete writes during large file sync are resolved using SHA-256 checksum comparison prior to atomic replacement.
- Rapid file modifications are managed by a 200ms debounce buffer inside `watch_skills.sh`.
- Stale lockfiles from abnormal process exits are automatically cleared if the holding process ID is dead or lock age exceeds 10 seconds.
- Missing target directories are created automatically with standard permissions (`0o755`).

### Implementation Steps

1. Update `scripts/sync_skills.py`
   - Implement `SkillRecord` and `SyncEngine` with SHA-256 caching and atomic file replication.
   - Add loop prevention check against `skills_sync_state.json` to prevent recursive event firing.
   - Implement the `--test-canary` verification command.

2. Update `scripts/watch_skills.sh`
   - Configure `fswatch` to monitor `~/projects/ai-os/skills`, `~/.claude/skills`, `~/.hermes/skills`, `~/.gemini/config/skills`, `~/.agents/skills`, and `~/.agy/skills`.
   - Route batch filesystem events to `scripts/sync_skills.py --sync-file`.

3. Execute End-to-End Canary Verification Test
   - The orchestrator invokes `python3 scripts/sync_skills.py --test-canary`.
   - Test step 1: Write `canary_sync_probe.md` to `~/projects/ai-os/skills/`.
   - Test step 2: Assert existence and identical SHA-256 hash in all 5 target platform skill directories.
   - Test step 3: Update `canary_sync_probe.md` inside `~/.hermes/skills/` and verify content propagation back to the repository and all other peers.
   - Test step 4: Remove `canary_sync_probe.md` and confirm deletion across the entire network.
