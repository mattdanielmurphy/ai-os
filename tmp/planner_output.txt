This plan details the architectural and implementation design to resolve screenshot attachment failures and introduce contextual auto-resumption of planner threads in `query_aios`.

## Architectural Strategy

The `query_aios` tool bridges agent interactions with the AI-OS runtime and planner sessions. 

For screenshot handling, failures stem from inconsistent handling of local file paths, base64 payloads, and MIME-type validation during IPC or HTTP transmission to the companion daemon. The revised strategy normalizes screenshot inputs into a structured media payload, standardizing resolution, base64 encoding, MIME sniffing, and payload verification before transmission.

For thread management, `query_aios` will bind Antigravity thread contexts to underlying planner threads using a persistent mapping registry (`~/.hermes/aios_thread_map.json` or `~/.gemini/antigravity-cli/brain/thread_links.json`). When invoked within an active Antigravity session, `query_aios` inspects the environment or session metadata:
- If the Antigravity thread ID has no prior linked planner thread, it provisions a fresh planner thread and stores the mapping.
- If an ongoing planner thread is mapped to that Antigravity thread ID, it defaults to resuming the existing thread.
- Explicit CLI flags (`--new-thread`, `--no-resume`, `--resume-thread <id>`, `--screenshot <path>`) allow agents and callers to override default resolution rules.

## State Management

The thread registry tracks lifecycle states, timestamps, and bi-directional thread mappings.

### Thread Association Schema (`aios_thread_map.json`)
```typescript
interface ThreadMappingEntry {
  antigravity_thread_id: string;
  planner_thread_id: string;
  created_at: string;
  last_active_at: string;
  turn_count: number;
  metadata?: {
    model?: string;
    last_status?: string;
  };
}

interface ThreadRegistryState {
  version: "1.0.0";
  mappings: Record<string, ThreadMappingEntry>;
}
```

### Media Attachment Schema

```typescript
interface ScreenshotAttachmentPayload {

  data_base64: string;
  file_path?: string;
  byte_size: number;

}
```

## Interface Contracts

### CLI Option Schema (`query_aios.js`)
```typescript
interface QueryAIOsCliFlags {
  prompt: string;
  screenshot?: string;            // File path, URL, or base64 string
  newThread?: boolean;           // Force start of a new planner thread (--new-thread, -n)
  resumeThread?: string;         // Explicit planner thread ID to resume (--resume <id>, -r <id>)
  noResume?: boolean;            // Disable auto-resumption without forcing map update (--no-resume)
  antigravityThreadId?: string;  // Explicit Antigravity thread ID context override (--ag-thread <id>)
  timeout?: number;              // Request timeout in milliseconds
}
```

## Logic Flow

```
1. CLI Argument Parsing & Context Discovery
   ├── Parse flags: --prompt, --screenshot, --new-thread, --resume, --no-resume, --ag-thread
   ├── Resolve current Antigravity thread ID:
   │   ├── Check --ag-thread flag
   │   ├── Check process.env.ANTIGRAVITY_THREAD_ID or process.env.HERMES_THREAD_ID
   │   └── Check active session log directory ~/.gemini/antigravity-cli/brain/
   └── If no AG thread ID detected -> agThreadId = null (standalone mode)

2. Planner Thread Resolution Algorithm
   ├── IF flags.resumeThread IS provided:
   │   └── Target plannerThreadId = flags.resumeThread (Explicit Override)
   ├── ELSE IF flags.newThread IS TRUE:
   │   └── Target plannerThreadId = null (Create New Thread)
   ├── ELSE IF flags.noResume IS TRUE:
   │   └── Target plannerThreadId = null (One-off Execution)
   ├── ELSE IF agThreadId is present:
   │   ├── Read registry from ~/.hermes/aios_thread_map.json
   │   ├── IF registry contains entry for agThreadId:
   │   │   └── Target plannerThreadId = entry.planner_thread_id (Auto-Resume)
   │   └── ELSE:
   │       └── Target plannerThreadId = null (Auto-New)
   └── ELSE:
       └── Target plannerThreadId = null

3. Screenshot Processing Pipeline
   ├── IF flags.screenshot IS provided:
   │   ├── Check if valid absolute or relative file path:
   │   │   ├── Resolve to absolute path via path.resolve()
   │   │   ├── Validate file existence via fs.statSync()
   │   │   ├── Verify file size <= 10MB limit
   │   │   ├── Read file buffer -> detect MIME type via magic bytes (PNG/JPEG/WebP)
   │   │   └── Encode to standard base64 string
   │   ├── ELSE IF string starts with "data:image/":
   │   │   └── Parse base64 header and extract buffer
   │   └── Package into standard ScreenshotAttachmentPayload
   └── Attach payload to IPC / API dispatch body

4. Execution & Post-Turn State Synchronization
   ├── Dispatch request to AI-OS loopback / daemon with prompt, target thread ID, and attachment
   ├── Receive response containing updated active plannerThreadId
   └── IF agThreadId is present AND flags.noResume is NOT TRUE:
       └── Update thread mapping registry with (agThreadId -> plannerThreadId, turn_count + 1, timestamp)
```

## Edge Cases

- **File Path Resolution Errors:** Screenshot paths from relative subdirectories fail if executed from varying working directories. All paths must be normalized against `process.cwd()` and tested with `fs.existsSync()` before constructing payloads.
- **Malformed Images or Unsupported Formats:** If a user passes an SVG or non-image file, reject before API transmission with a clear validation error detailing supported image formats.
- **Stale or Purged Planner Threads:** If `query_aios` attempts to resume a planner thread that has expired or was removed on the backend, catch the 404/Not Found response, invalidate the cache entry in `aios_thread_map.json`, and automatically retry as a new thread.
- **Concurrent Turn Collisions:** Use atomic file writes or lightweight lock files when reading/updating `aios_thread_map.json` to avoid race conditions across parallel subagent executions.
- **Headless Environments without Antigravity ID:** When run outside Antigravity (e.g., standard CLI or CI), default gracefully to standalone single-shot or explicit thread IDs without crashing on missing environment keys.

## Implementation Steps

- **Step 1: Attachment Normalizer Module (`scripts/lib/attachment_helper.js`)**
  - Implement `resolveScreenshotAttachment` to handle absolute/relative path resolution, buffer conversion, MIME type sniffing, and base64 packaging with boundary checks.
- **Step 2: Thread Mapping Registry Manager (`scripts/lib/thread_resolver.js`)**
  - Implement read, write, and invalidate functions for `~/.hermes/aios_thread_map.json`.
  - Implement Antigravity thread ID detection via environment variables and CLI argument fallback.
  - Implement thread ID selection rules respecting `--new-thread`, `--resume <id>`, and `--no-resume`.
- **Step 3: Update Main CLI Harness (`scripts/query_aios.js`)**
  - Add argument flags: `--screenshot`, `--new-thread` (`-n`), `--resume` (`-r`), `--no-resume`, and `--ag-thread`.
  - Wire attachment normalizer into request payload assembly.
  - Wire thread resolver into conversation lifecycle logic and handle automatic 404 retry fallback.
  - Update mapping state on successful turn completion.
- **Step 4: Update AI-OS / Hermes Skills & Tools Configuration (`skills/ai-os/`, `tools/`)**
  - Update tool description schemas and skill documentation with the new flags and attachment examples.
- **Step 5: Unit & Integration Tests (`tests/test_query_aios.py` or Jest suites)**
  - Test screenshot attachment with valid paths, missing paths, and raw base64 strings.
  - Test auto-resume on consecutive invocations with the same `ANTIGRAVITY_THREAD_ID`.
  - Test thread reset behavior when passing `--new-thread` on an existing thread.
