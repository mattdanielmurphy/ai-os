The conversation history lock occurs because Antigravity IDE encountered a deserialization crash in its extension host after unformatted data was written directly into the SQLite database while the application was active. Direct modification of `state.vscdb` violated the IDE's internal state schema and bypassed the active process memory cache, triggering a safety error boundary that disabled the past conversations UI and halted the `@conversation:` completion provider.

## Root Cause Diagnosis

The UI lock state is the downstream result of three distinct failure modes interacting across the database, extension host, and renderer tiers:

1. SQLite Lock Contention and Memory Divergence: Antigravity IDE maintains an open SQLite connection with write-ahead logging to `state.vscdb`. Modifying this file externally while the IDE process runs desynchronizes the in-memory memento cache and leaves incomplete WAL transactions, causing read timeouts or corruption flags.
2. Schema Deserialization Exceptions: Antigravity IDE expects strict TypeScript schemas under `ItemTable` keys like `workbench.panel.aichat.view.aichat.chatdata` and `interactive.sessions`. Raw injection from `Antigravity.app` threads omitted critical metadata fields, such as `bubbleId`, `workspaceId`, `generationUUID`, and `schemaVersion`, causing `JSON.parse` or Zod runtime validation to throw unhandled exceptions.
3. UI Error Boundary Activation: When the conversation list component fails to hydrate the deserialized session tree, it catches the exception and renders an inactive, fallback state. This applies the CSS rule `cursor: not-allowed` across thread elements and prevents the extension host from registering the `@conversation:` mention provider.

| Issue Vector | Raw Injection Mechanism | Failure Symptom in IDE |
| :--- | :--- | :--- |
| Concurrency | Direct write during runtime | WAL corruption, lock error, stale state  |
| Schema Integrity | Missing required IDE JSON fields | Extension host runtime TypeError  |
| Workspace Scope | Missing hash association | `@conversation:` completion provider failure |
| UI State | Unhandled hydration rejection | Disabled crosshair cursor (`not-allowed`)  |

## Architectural Strategy and Contracts

The safe approach replaces raw database modification with an offline, validated synchronization bridge that normalizes `Antigravity.app` NDJSON transcripts and Hermes SQLite entries into the exact schema required by Antigravity IDE.

The bridge operates strictly when Antigravity IDE is stopped, or alternatively interfaces through a dedicated background Language Server Protocol (LSP) / VS Code extension API that supplies conversation references dynamically.

## Logic Flow and Algorithms

The safe import procedure coordinates process verification, data normalization, database backup, and atomic writing:

1. Process Guard: Query the system process table for `antigravity` or `electron` binary instances matching the IDE. If active, abort and instruct the user to close the IDE before writing to avoid database locks.
2. Workspace Hash Resolution: Compute or read the target workspace hash from `workspaceStorage` to ensure conversation records are correctly bound to the active workspace.
3. Transcript Parsing: Ingest NDJSON session logs from `~/.gemini/antigravity-cli/brain/` and SQLite records from `~/.hermes/state.db`.
4. Schema Transformation: Transform turns and messages into standard IDE bubbles, populating default UUIDs, timestamp integers, and schema version identifiers.
5. Backup Creation: Copy existing `state.vscdb` to `state.vscdb.backup.<timestamp>` prior to executing transactions.
6. Transactional Upsert: Open a connection to SQLite, parse existing records under `workbench.panel.aichat.view.aichat.chatdata`, merge new thread entries without overwriting existing IDs, and execute an `UPSERT` statement inside an explicit transaction.
7. Post-Write Verification: Read back the updated row and run a validation parse on the JSON payload before committing changes to disk.

```python
# Pseudo-code for Safe Execution Flow
def run_safe_import(workspace_path, app_source_path):
    adapter = AntigravityBridgeAdapter()
    if adapter.check_ide_running():
        raise ProcessLookupError("Antigravity IDE must be closed before importing.")
    
    workspace_hash = get_workspace_hash(workspace_path)
    db_path = get_storage_path(workspace_hash)
    
    raw_threads = adapter.extract_app_threads(app_source_path)
    normalized = adapter.normalize_to_ide_schema(raw_threads, workspace_hash)
    
    success = adapter.atomic_safe_write(db_path, normalized)
    return success
```

## Edge Cases and Implementation Steps

Handling corrupt or partially written states requires specific fallback routines to preserve data integrity:

- Corrupted Database Recovery: If `state.vscdb` is unreadable, quarantine the file to `state.vscdb.corrupted.<timestamp>` and initialize a clean database structure from template.
- Missing Hash Directory: If `workspaceStorage/<hash>` does not exist yet, resolve the global database path or trigger initial directory initialization.
- Lock Timeouts: Use SQLite timeout configurations (`PRAGMA busy_timeout = 5000;`) to avoid instantaneous failure on slow disk locks.
- Schema Version Drift: Inspect the version field of existing `chatdata` records; if newer than known formats, preserve raw extra keys to avoid breaking downstream features.
