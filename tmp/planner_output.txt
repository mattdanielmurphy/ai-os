This implementation plan defines the addition of the `/api/health` diagnostic endpoint to the loopback HTTP daemon in `apps/gemini-companion/src-tauri/src/server.rs` and the FastAPI proxy in `services/agy-proxy/proxy.py`. The endpoint allows frontend components, background daemons, and orchestrator health probes to verify daemon liveness and runtime subsystem status.

## Architectural Strategy

The health check route exposes a lightweight, non-blocking `GET /api/health` endpoint across the system's local server layers . For the Rust loopback daemon in `apps/gemini-companion`, the route matches incoming HTTP request paths and returns runtime metadata including process uptime, version, active session counts, and subsystem readiness states. For `services/agy-proxy`, a corresponding route is registered on the FastAPI application instance to validate proxy availability and CLI executable connectivity.

Both endpoints conform to standard REST conventions by returning HTTP 200 OK with a structured JSON payload when healthy, and HTTP 503 Service Unavailable if critical dependencies fail to initialize.

## Data Structures and State

The endpoint introduces typed status response schemas in both Rust and Python server contexts.

```rust
// Rust Loopback Daemon: apps/gemini-companion/src-tauri/src/types.rs (or server.rs)
#[derive(serde::Serialize, serde::Deserialize, Debug, Clone)]
pub struct SubsystemHealth {
    pub pty_ready: bool,
    pub session_store_ready: bool,
    pub git_bridge_ready: bool,
}

#[derive(serde::Serialize, serde::Deserialize, Debug, Clone)]
pub struct HealthCheckResponse {
    pub status: String,          // "ok" | "degraded" | "error"
    pub version: String,         // Cargo package version
    pub uptime_seconds: u64,     // Server instance uptime
    pub active_threads: usize,   // Active managed PTY/session threads
    pub subsystems: SubsystemHealth,
}
```

```python
# FastAPI Proxy Daemon: services/agy-proxy/proxy.py
from pydantic import BaseModel
from typing import Dict, Optional

class ProxyHealthResponse(BaseModel):
    status: str                  # "ok" | "error"
    service: str                 # "agy-proxy"
    version: str
    agy_cli_available: bool      # Verifies local agy CLI binary existence
    active_sessions: int
    details: Optional[Dict[str, str]] = None
```

## API Contracts and Interfaces

The API interface contract is standardized for both consumer clients and monitoring scripts.

- **HTTP Method:** `GET`
- **Path:** `/api/health`
- **Request Headers:** None required (`Accept: application/json` optional)
- **Response Headers:** `Content-Type: application/json`, `Access-Control-Allow-Origin: *` (for Webview/CORS compatibility)
- **Response Status Codes:**
  - `200 OK`: Server running normally; all core subsystems initialized.
  - `503 Service Unavailable`: Server running, but a critical prerequisite failed.

## Execution Logic and Flow

The server evaluates internal subsystem state before building and serializing the response payload.

1. **Request Ingress:** The HTTP request arrives at the loopback server dispatch loop.
2. **Path Matching:** The router checks if `request.method() == Method::Get` and `request.path() == "/api/health"`.
3. **Subsystem Verification:**
   - Query global application state for lock contention or thread liveness.
   - Calculate elapsed process uptime from the recorded startup timestamp `Instant::now()`.
   - In `proxy.py`, execute a non-blocking `shutil.which("agy")` check to confirm binary availability.
4. **Payload Construction:** Map the gathered states into `HealthCheckResponse` or `ProxyHealthResponse`.
5. **Serialization and Dispatch:** Serialize the payload to JSON format, attach CORS and content-type headers, and return HTTP 200.

## Error Handling and Implementation Steps

Any failure during status aggregation must degrade gracefully without crashing the server loop.

- **Lock Contention:** If acquiring read locks on `AppState` times out or fails, return `status: "degraded"` with partial metrics rather than dropping the socket connection.
- **Serialization Failures:** Fall back to a static string literal JSON response `{"status":"ok"}` if struct serialization fails.
- **File Modifications (Execution Order):**
  1. `apps/gemini-companion/src-tauri/src/types.rs`: Add `SubsystemHealth` and `HealthCheckResponse` structs with `Serialize`/`Deserialize` derives.
  2. `apps/gemini-companion/src-tauri/src/server.rs`: Record server initialization timestamp in `AppState` or the server listener loop. Add the `/api/health` branch to the request match block, dispatching the response with standard CORS headers.
  3. `services/agy-proxy/proxy.py`: Define `ProxyHealthResponse` Pydantic model and attach `@app.get("/api/health")` checking CLI binary existence and active session counts.
  4. `apps/gemini-companion/src/utils/health.ts` (optional client helper): Export a ping function `checkServerHealth(): Promise<boolean>` for UI status indicators.
  5. `scripts/preflight.py` (or test runner): Add verification test cases sending `GET /api/health` to validate HTTP 200 responses.
