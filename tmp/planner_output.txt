Past conversations fail to load in the Antigravity IDE UI due to a desynchronization between `state.vscdb` extension storage keys, SQLite trajectory protobuf blob schemas in `~/.gemini/antigravity-ide/conversations/`, and strict parsing expectations in the `language_server` RPC handler for `trajectorySummaries`. The definitive fix establishes a resilient trajectory hydration pipeline that normalizes storage paths, repairs schema deserialization, and ensures binary invocation flags align with the vendor language server contract.

***

### Architectural Strategy

The remediation architecture resolves conversation loading across three coupled layers: runtime binary invocation, data persistence, and RPC communication.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           Antigravity IDE UI                            │
│                 (VS Code Extension Webview / Chat Panel)                 │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ JSON-RPC (stdio)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│            Vendor Language Server (language_server_macos_arm)           │
│                                                                         │
│  ┌───────────────────────┐             ┌─────────────────────────────┐  │
│  │ trajectorySummaries   │             │   loadTrajectory RPC        │  │
│  │ RPC Handler           │             │   Handler                   │  │
│  └───────────┬───────────┘             └──────────────┬──────────────┘  │
│              │                                        │                 │
│              ▼                                        ▼                 │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ Resilient Protobuf Deserializer & Fallback Summary Parser         │  │
│  └───────────────────────────────────┬───────────────────────────────┘  │
└──────────────────────────────────────┼──────────────────────────────────┘
                                       │
        ┌──────────────────────────────┴──────────────────────────────┐
        ▼                                                             ▼
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│        Workspace state.vscdb         │  │     ~/.gemini/antigravity-ide/       │
│ (VS Code Global / Workspace Storage) │  │          conversations/*.db          │
│   - Extension metadata & UI cache    │  │   - SQLite trajectory protobuf blobs │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
```

The approach enforces direct vendor binary execution without stdio-buffering shims, standardizes conversation database discovery across workspace roots, and wraps protobuf payload decoding in a fault-tolerant parser to prevent individual corrupted transcripts from blocking UI rendering.

| Layer | Failure Mechanism | Architectural Resolution |
| :--- | :--- | :--- |
| **Binary Invocation** | Missing `--storage-dir` or `--workspace-id` args | Standardize launcher flags and environment bindings |
| **Persistence (SQLite)** | Database locks or schema mismatch in trajectory blobs | Schema validation and WAL-mode database connection |
| **UI State (`state.vscdb`)** | Stale workspace GUID mappings and cache misses | Re-index state keys matching active workspace path hash |
| **RPC & Deserialization** | Missing fields in `trajectorySummaries` protobuf | Backward-compatible schema decoding with fallbacks |

### Data Structures & State Management

The conversation state resides in both SQLite trajectory stores and the VS Code `state.vscdb` database.

#### 1. Trajectory Protobuf Schema
```protobuf
syntax = "proto3";
package antigravity.trajectory;

message TrajectoryMetadata {
  string conversation_id = 1;
  string title = 2;
  int64 created_at_ms = 3;
  int64 updated_at_ms = 4;
  string workspace_path = 5;
  int32 total_steps = 6;
  string model_name = 7;
}

message TrajectoryStep {
  string step_id = 1;
  string role = 2; // "user", "assistant", "system", "tool"
  string content = 3;
  int64 timestamp_ms = 4;
  repeated ToolCall tool_calls = 5;
  string error_message = 6;
}

message ToolCall {
  string tool_name = 1;
  string call_id = 2;
  string arguments_json = 3;
  string result_json = 4;
  int32 status_code = 5;
}

message Trajectory {
  TrajectoryMetadata metadata = 1;
  repeated TrajectoryStep steps = 2;
}

message TrajectorySummary {
  string conversation_id = 1;
  string title = 2;
  int64 created_at_ms = 3;
  int64 updated_at_ms = 4;
  int32 step_count = 5;
  string snippet = 6;
  string workspace_id = 7;
}

message TrajectorySummariesResponse {
  repeated TrajectorySummary summaries = 1;
  int32 total_count = 2;
}
```

#### 2. SQLite Database Schema (`~/.gemini/antigravity-ide/conversations/`)
```sql
CREATE TABLE IF NOT EXISTS conversation_trajectories (
    conversation_id TEXT PRIMARY KEY,
    workspace_hash TEXT NOT NULL,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    title TEXT,
    step_count INTEGER DEFAULT 0,
    protobuf_blob BLOB NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_trajectories_workspace 
ON conversation_trajectories(workspace_hash, updated_at DESC);
```

#### 3. `state.vscdb` Storage Keys
- Extension Cache Key: `antigravity.conversations.cachedSummaries.<workspace_hash>`
- Active Conversation ID: `antigravity.activeConversationId`
- Storage Directory Override: `antigravity.storageDirectory`

### API & Interface Contracts

The interface contract standardizes communication between the extension client and the `language_server` binary.

#### 1. Language Server Launch Contract
```bash
/Applications/Antigravity\ IDE.app/Contents/Resources/app/extensions/antigravity/bin/language_server_macos_arm \
  --stdio \
  --storage-dir="$HOME/.gemini/antigravity-ide" \
  --workspace-id="<WORKSPACE_SHA256>" \
  --log-level="info"
```

#### 2. LSP / JSON-RPC Endpoints
```typescript
interface TrajectoryRPCInterface {
  /**
   * Fetches metadata summaries for all past conversations in the current workspace.
   */
  getTrajectorySummaries(params: {
    workspaceId: string;
    limit?: number;
    offset?: number;
  }): Promise<{
    summaries: Array<{
      conversationId: string;
      title: string;
      createdAt: number;
      updatedAt: number;
      stepCount: number;
      snippet: string;
    }>;
    totalCount: number;
  }>;

  /**
   * Loads the full step history for a specific conversation ID.
   */
  loadTrajectory(params: {
    conversationId: string;
  }): Promise<{
    conversationId: string;
    metadata: Record<string, unknown>;
    steps: Array<{
      stepId: string;
      role: 'user' | 'assistant' | 'system' | 'tool';
      content: string;
      timestamp: number;
      toolCalls?: Array<Record<string, unknown>>;
    }>;
  }>;

  /**
   * Deletes or archives a past trajectory from disk and state.
   */
  deleteTrajectory(params: {
    conversationId: string;
  }): Promise<{ success: boolean }>;
}
```

### Logic Flow & Algorithms

The conversation recovery and loading workflow executes deterministic hydration with defensive fallbacks.

#### 1. Language Server Initialization & DB Discovery
```
1. Extension client starts language_server_macos_arm via stdio with workspace-id.
2. Binary resolves storage directory ~/.gemini/antigravity-ide/conversations/.
3. Server executes PRAGMA journal_mode=WAL and PRAGMA busy_timeout=5000 on conversation databases.
4. Server verifies trajectory schema and triggers lightweight migration if legacy columns exist.
```

#### 2. Resilient `trajectorySummaries` Extraction Algorithm
```python
def extract_trajectory_summaries(db_path: str, workspace_hash: str) -> list[dict]:
    summaries = []
    conn = sqlite3.connect(db_path, timeout=5.0)
    cursor = conn.cursor()
    
    query = """
        SELECT conversation_id, title, created_at, updated_at, step_count, protobuf_blob 
        FROM conversation_trajectories 
        WHERE workspace_hash = ? OR workspace_hash = 'global'
        ORDER BY updated_at DESC
    """
    
    for row in cursor.execute(query, (workspace_hash,)):
        conv_id, title, created_at, updated_at, step_count, blob = row
        try:
            # Primary path: strict protobuf decode
            trajectory = Trajectory()
            trajectory.ParseFromString(blob)
            
            snippet = ""
            if trajectory.steps:
                snippet = trajectory.steps[0].content[:120]
                
            summaries.append({
                "conversationId": conv_id,
                "title": title or trajectory.metadata.title or "Untitled Conversation",
                "createdAt": created_at or trajectory.metadata.created_at_ms,
                "updatedAt": updated_at or trajectory.metadata.updated_at_ms,
                "stepCount": step_count or len(trajectory.steps),
                "snippet": snippet
            })
        except Exception:
            # Fallback path: extract raw string heuristics if protobuf decoding fails
            summaries.append({
                "conversationId": conv_id,
                "title": title or f"Recovered Session ({conv_id[:8]})",
                "createdAt": created_at or 0,
                "updatedAt": updated_at or 0,
                "stepCount": step_count or 1,
                "snippet": "Preview unavailable (recovered trajectory)"
            })
            
    conn.close()
    return summaries
```

#### 3. State Reconciliation & UI Sync Flow
```
1. Webview sends 'antigravity/getTrajectorySummaries' request via extension host.
2. Extension host checks state.vscdb cache:
   a. If cached summaries exist and TTL < 30s, return cached list.
   b. If cache missed or stale, invoke language_server RPC.
3. If language_server returns an empty list or RPC times out:
   a. Fall back to local SQLite directory reader in scripts/sync_antigravity_ide.py.
   b. Parse .db trajectory records directly using fallback parser.
   c. Hydrate state.vscdb with the recovered summaries.
4. UI renders conversation drawer with recovered conversation cards.
5. On conversation selection, UI calls loadTrajectory(conversationId).
```

### Implementation Steps

The execution steps are ordered sequentially to diagnose, repair, and verify conversation loading without risking active workspace data.

- Step 1: **Sanitize Language Server Execution Environment**
  Verify that `/Applications/Antigravity IDE.app/Contents/Resources/app/extensions/antigravity/bin/language_server_macos_arm` is the unmodified vendor binary. Ensure no active wrappers, stdin buffers, or defunct shims intercept the stdio stream.

- Step 2: **Audit & Repair SQLite Trajectory DBs in `~/.gemini/antigravity-ide/conversations/`**
  Run an integrity check across all `.db` files in the conversations folder. Remove any stale SQLite `-shm` and `-wal` lock files left by crashed processes. Ensure all records have a valid `workspace_hash` matching the SHA256 of the current workspace root.

- Step 3: **Update Bridge Script `scripts/sync_antigravity_ide.py`**
  Add robust protobuf decoding with a defensive fallback parser. Ensure it extracts `conversation_id`, `title`, `updated_at`, and `step_count` even when optional protobuf metadata tags are absent.

- Step 4: **Rebuild `state.vscdb` Conversation Cache**
  Add a repair routine in `scripts/extract_antigravity_titles.py` to populate `state.vscdb` global storage keys with valid trajectory summary JSON arrays for each discovered conversation.

- Step 5: **Validate RPC Contract via End-to-End Test**
  Execute `tests/test_antigravity_sync.py` to simulate `getTrajectorySummaries` and `loadTrajectory` JSON-RPC calls over stdio, verifying that all past conversations return HTTP 200 / JSON-RPC success responses and render correctly in the IDE interface.
