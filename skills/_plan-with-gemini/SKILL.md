# Plan With Gemini (High Reasoning Subagent)

Initiate deep, high-reasoning implementation planning for complex, ambiguous, or multi-step tasks by spawning a planning subagent running Gemini 3.7 High (`Gemini 3.7 Flash (High)`).

Unlike `_plan-with-ai-os` (which dispatches out-of-band via Perplexity and requires a GitHub remote connector), this skill executes locally with direct workspace filesystem access, eliminating the need for GitHub sync, staging, or remote pushes.

---

## Workflow Steps

### 1. Sanity Check & Scope Formulation
- Identify the target project root, active workspace files, and the user's core requirements.
- Direct local filesystem access is used (no GitHub remote check or push required).

### 2. Dispatch Planning Subagent via `agymcp`
- Dispatch to a high-reasoning subagent running `Gemini 3.7 Flash (High)` via `agymcp:agy` (or `agymcp:agy_start`).
- Pass a structured planning prompt instructing the subagent to:
  1. Inspect `AG_CONTEXT.md`, `DEVELOPMENT_JOURNAL.md`, and relevant codebase files directly.
  2. Perform root cause analysis and explore edge cases.
  3. Include the mandatory attribution header at the top of the plan:
     ```markdown
     > [!NOTE]
     > **Generated By**: Gemini 3.7 Flash (High) (via agymcp planning subagent)
     ```
  4. Produce a structured implementation plan with:
     - **Goal Description**
     - **User Review Required** (`> [!IMPORTANT]`, `> [!WARNING]`)
     - **Open Questions**
     - **Proposed Changes** (`[MODIFY]`, `[NEW]`, `[DELETE]`)
     - **Verification Plan** (automated tests and manual checks)
  5. Write the plan to `<appDataDir>/brain/<conversation-id>/implementation_plan.md`.

### 3. Handle Dispatch Failures Transparently (Zero Silent Fallback)
- **Strict Anti-Deception Invariant**: If `agymcp` returns an error or fails to execute:
  1. **Immediate Failure Disclosure**: The orchestrator MUST immediately surface the raw error message to the user.
  2. **Do NOT Self-Generate Deceptively**: The orchestrator must NEVER silently absorb the failure and write the plan itself pretending the requested model produced it.
  3. **Provide Next Steps**: State the active orchestrator model and offer clear options: retry dispatch, fallback to alternative high-reasoning engine (e.g. Perplexity Gemini Flash Thinking), or ask if the user wants the orchestrator model to write the plan directly.

### 4. Present Plan for Approval
- Ensure `implementation_plan.md` has `user_facing: true` and `request_feedback: true`.
- Await user approval before proceeding to implementation.
