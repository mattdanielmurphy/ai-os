# Proactive System Directive & Knowledge Persistence
- **Promises to remember must be saved rules (Matt, 2026-10-29)**: agents are ephemeral; "I'll remember" or "from now on I'll" stores nothing. Any "always / never / from now on" instruction from Matt is a global rule for every coordinator and agent, forever, unless he narrows it: save it here in `.rules/`, run `build_rules.py`, commit and push, then confirm in one line. Matt: "agents forget they're ephemeral and they think they can just 'remember' something by telling themselves to remember it, rather than actually making it a rule that's stored on a disk." Enforced by `scripts/hooks/rule_prompt_nudge.py` (UserPromptSubmit) and `rule_promise_guard.py` (Stop, blocks a promise when no rule file changed).
- **Rule**: When Matt establishes a permanent workflow preference, tool routing rule, or operational invariant (e.g. "always do X from now on" or "agents must know this in every thread"):
  - Agents MUST NOT bury it in an obscure notes file that won't be read.
  - Agents MUST immediately update the single-source rules under `~/projects/ai-os/.rules/` and run `python3 ~/projects/ai-os/scripts/build_rules.py` so the directive is compiled into `GEMINI.md` and `CLAUDE.md` across every future session.
  - **Say it's global, every time (Matt, 2026-10-27)**: whenever you save a rule Matt gives, your reply confirms it in one plain line, e.g. "**Saved as a global rule**: it applies in every project, thread and agent, and it syncs to Tyler via slub-hq." Why: Matt: "when I give an instruction like that, I need to know that it'll be global, and that we can share it and our entire setup with Tyler via the slub-hq repo."
  - **Shared with Tyler (2026-10-27)**: `scripts/export_setup.py` (run automatically at the end of `build_rules.py`) writes a sanitized copy of the rules, the coordinator doc and Matt's `_` skills to `~/projects/slub-hq/setup/matt/` and pushes it. It strips home paths, emails, phone numbers and lines naming private files; never put private details into rules in the first place.
  - **Scope is global by default (2026-10-20)**: Any rule or preference Matt gives applies everywhere: every project, thread, Code session, Claude Projects, and every agent (Claude, Gemini, Codex), unless he explicitly limits it to one project or thread. Save it globally (here, `~/.claude/CLAUDE.md`, and the current project's instructions when one exists). **Exception, guess-and-confirm when scope is genuinely ambiguous (Matt, 2026-10-29)**: when a rule plainly names something specific to one project ("never do X" where X only exists there), save it with your best guess and confirm in one line before moving on: "Quick check: I saved this as a project-only rule for <project>, right?" (or global, right?). Matt: "the agent should be aware of roughly how much of a guess they're making and what the consequences are of being wrong." Clear cases still get no question.
  - **Know how big your guesses are (Matt, 2026-10-29)**: agents must make assumptions to be useful, but should know roughly how much they're guessing and what being wrong would cost. Cheap, reversible guesses: just act. Costly or hard-to-undo guesses: state the guess in one line and confirm before going on.
