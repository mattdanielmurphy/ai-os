### Option 1: RenderCV Template Override (Cleanest & 100% YAML-Native)
In RenderCV, the entire header block is controlled by `design.templates.header` in [`darryl_murphy_cv.yaml`](file:///Users/matt/projects/job-applier/darryl_murphy_cv.yaml) [](http://127.0.0.1:8643/open_zed?path=/Users/matt/projects/job-applier/darryl_murphy_cv.yaml) [](http://127.0.0.1:8643/open_finder?path=/Users/matt/projects/job-applier/darryl_murphy_cv.yaml).

By adding a Typst vertical space (`#v(0.3in)` or whatever amount you want) right above the `NAME` placeholder, RenderCV will inject top spacing **exclusively above the name on Page 1**, leaving Page 2's top margin untouched:

```yaml
design:
  templates:
    header: |-
      #v(0.4in)
      NAME
      HEADLINE
      CONNECTIONS
```

* **Why this is great**:
  - Affects **Page 1 only** (since the header only exists on Page 1).
  - Keeps everything in your single YAML source of truth.
  - You can dial in the exact spacing you want (e.g. `0.25in`, `0.5cm`, `1cm`).

### Root Cause of the Crash:
The error `RuntimeError: Already borrowed` is an upstream race condition in RenderCV's built-in `-w` / `--watch` mode on macOS:
- When a file modification event fires, the Python `watchdog` library triggers rapid re-renders concurrently on background threads.
- Because the underlying Rust `typst` compiler binding in Python is not thread-safe for concurrent compilation calls on the same instance, it throws `RuntimeError: Already borrowed` and crashes the thread.

   - **Build queue serialization** (guarantees that subsequent file edits wait for the current compilation to finish cleanly before triggering the next one).
