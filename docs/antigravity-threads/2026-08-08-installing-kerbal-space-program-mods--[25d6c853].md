### How KSP Mod Installation Works on macOS

In Kerbal Space Program (KSP 1), all mods are installed directly into the game's **`GameData`** folder.

1. **Standard KSP GameData Location (Steam on macOS)**:
   ```text
   ~/Library/Application Support/Steam/steamapps/common/Kerbal Space Program/GameData/
   ```
2. **Folder Structure**:
   Each mod folder (e.g., `AutoQuickSaveSystem`) sits directly inside `GameData/`, alongside the default `Squad` and `SquadExpansion` folders:
   ```text
   GameData/
   ├── Squad/
   ├── SquadExpansion/
   └── AutoQuickSaveSystem/
       ├── Plugins/
       │   └── AQSS.dll
       ├── PluginData/
       ├── Audio/
       └── AutoQuickSaveSystem.version
   ```

## Assistant

**Yes, absolutely.**

In the context of **Kerbal Space Program (and Unity games in general)**, `.dll` files work seamlessly on macOS.

### Why it works:
1. **Unity & Mono/.NET**: KSP is built on the Unity engine, which uses Mono (an open-source .NET runtime).
2. **Bytecode, Not Native Windows Code**: In C# / .NET development, compiled code is saved as `.dll` files containing **CIL bytecode** (Common Intermediate Language) rather than native Windows machine code (`.exe`/`.dll` binary).
3. **Cross-Platform JIT Execution**: When KSP loads on macOS, Unity's Mono runtime reads the `.dll` and JIT-compiles it directly for macOS in memory.

As long as a mod doesn't rely on Windows-specific system calls (which utility/gameplay mods like `AutoQuickSaveSystem` do not), KSP `.dll` mods are **100% cross-platform** across macOS, Linux, and Windows.
