* A negative $A$ reflects the graph over the $x$-axis.




* Horizontal Transformations ($y = f(Bx)$):

* Replacing $x$ with $Bx$ divides all $x$-coordinates by $B$, resulting in a horizontal stretch or compression.





5. Inverse Functions

* Definition: If $f(x) = y$, then $f^{-1}(y) = x$. Two functions are inverses if $f^{-1}(f(x)) = x$ and $f(f^{-1}(y)) = y$.

* Finding an Inverse:

* Write the equation as $y = \dots$

* Solve for $x$.

* Write $x$ as $f^{-1}(y)$.

* Rewrite $f^{-1}(y)$ as a function of $x$ (optional, but standard).




* Inverse Trig Functions: Always return an angle. They require restricted domains to remain one-to-one and invertible (pass the horizontal line test).


6. Exponential & Logarithmic Functions

* Forms:

* Exponential: $y = C \cdot A^x$ (where $A$ is the base/rate of change).

* Logarithmic: $y = C \cdot \log_A(x)$.

function renderBlock(latex) {
    let processedLatex = latex.trim()
    if (processedLatex.includes('\\begin{aligned}')) {
        // Only add significant vertical spacing if there's a fraction in the block
        const hasFraction = /\\(d?frac|t?frac|over)/.test(processedLatex)
        const spacing = hasFraction ? '0.65em' : '0.35em' // Bumped from 0.6em/0.1em
        processedLatex = processedLatex.replace(
            /\\\\(?!\s*\[)/g,
            `\\\\[${spacing}]`
        )
    }
    try {
        return katex.renderToString(processedLatex, {
            displayMode: true,
            throwOnError: false,
            output: 'html',
        })
    } catch (e) {
        return `<pre class="katex-error">${processedLatex}</pre>`
    }
}

function renderInline(latex) {
    try {
        return katex.renderToString(latex.trim(), {
            displayMode: false,
            throwOnError: false,
            output: 'html',
        })
    } catch (e) {
        return `<code class="katex-error">${latex}</code>`

}

function storeMath(latex, isBlock) {
    let processed = latex

    // Handle automatic bolding for math inside bold markdown
    if (processed.startsWith('__AUTOBOLD__')) {
        processed = processed.slice(12).trim()
        // Wrap in \boldsymbol and change \text to \textbf
        processed = `\\boldsymbol{${processed.replace(/\\text\{/g, '\\textbf{')}}`
    }

    processed = processed
        // Pull equals signs out of bold commands so they retain proper mathematical spacing
        // e.g., \boldsymbol{r = } becomes \boldsymbol{r} =
        .replace(
            /(\\boldsymbol|\\mathbf|\\textbf)\{([^}]*?)\s*=\s*\}/g,
            '$1{$2} = '
        )
        // Handle cases where the equals is in the middle: \boldsymbol{a = b} -> \boldsymbol{a} = \boldsymbol{b}
        .replace(
            /(\\boldsymbol|\\mathbf|\\textbf)\{([^}]*?)\s*=\s*([^}]*?)\}/g,
            '$1{$2} = $1{$3}'
        )

    const id = `@@MATH${mathCounter++}@@`
    const html = isBlock ? renderBlock(processed) : renderInline(processed)
    mathMap.set(id, html)
    return id
}

## Gemini

To generate decent-looking graphs "live" within your Markdown files, the best approach is to move away from manually inserting static image files and instead use a tool that generates diagrams on-the-fly from code.


Since you are already using Node.js and Puppeteer to render your Markdown to PDF, you can integrate a diagramming engine directly into your build script.


1. Recommended Tool: Mermaid.js
Mermaid is the industry standard for this. It allows you to write simple code blocks in your Markdown that render into professional diagrams, including function plots, flowcharts, and sequence diagrams.


Why it fits your setup:



* Text-based: You can edit the graph code right next to your text.

* "Decent" look: It produces clean, SVG-based diagrams that look great in PDFs.

* Integration: You can easily inject a script into your pdf-exporter.js to parse these code blocks and render them into SVGs during the build.


2. Implementation Strategy
To integrate this without changing your workflow, follow these steps:


Step A: Add to your Markdown
In your .md files, just use code blocks marked with mermaid:


```mermaid
graph TD
    A[Hard Work] --> B(Success)

xychart-beta
    title "Function Plot: f(x) = x^2"
    x-axis [0, 1, 2, 3, 4]
    y-axis "f(x)" 0 --> 16
    line [0, 1, 4, 9, 16]


#### Step B: Update your `pdf-exporter.js`
You need to tell your script to look for `mermaid` code blocks and convert them to HTML/SVG.

1.  **Install Mermaid:** Run `npm install mermaid` in your project folder.
2.  **Modify the script:**
    * Add `const mermaid = require('mermaid');` to the top.
    * In the rendering section (where you call `marked`), you can use a custom renderer or a regex to replace these blocks with the rendered SVG output provided by `mermaid.render()`.
    * *Note:* Since `mermaid` usually runs in the browser, if you want to keep the build fast, you can use the `mermaid` CLI to pre-process these blocks, or use a library like `mermaid-cli` to export them to SVGs before your script runs.

### 3. An Even Easier "No-Code" Alternative
If you prefer not to write complex logic into your build script, use an **API-based approach**. 

You can use [QuickChart.io](https://quickchart.io/), which allows you to generate a chart by simply constructing a URL. You don't need to install anything.

**How it works:**
1.  Define your chart in a simple JSON-like URL format.
2.  In your markdown, just use a standard image tag:
    `![Graph](https://quickchart.io/chart?c={type:'line',data:{labels:[0,1,2,3],datasets:[{label:'f(x)',data:[0,1,4,9]}]}})`
3.  Your current `pdf-exporter.js` already handles `img` tags perfectly. When Puppeteer opens your generated HTML, it will fetch the chart image from the web and embed it in your PDF automatically.

### Summary
* **If you want control and professional, themeable charts:** Use [Mermaid.js](https://mermaid.js.org/). It requires a small tweak to your `node` script to process the code blocks, but it keeps everything local and offline-capable.
* **If you want the "fastest" way to start today:** Use [QuickChart.io](https://quickchart.io/). It requires zero changes to your `node` script because it relies on simple `<img>` tags that your script already supports.

Do you have a preference for keeping the diagram code local within the Markdown file, or are you comfortable using image URLs for the charts?

Why this is better than images:

* Vector Quality: Since it's SVG, the graphs will be perfectly sharp in your PDF, no matter the zoom level.

* Agent Friendly: It’s much easier for an AI to write a JSON config than to generate and save an image file and manage the path.

* Live Tweaking: You can change the domain or the function in your .md file and see the result immediately when you run your exporter.


Quick Tip for your Puppeteer script:
Because functionPlot takes a few milliseconds to draw the SVG, you should update your await page.evaluate block to ensure it waits for the SVGs to appear. You can add a small check:


await page.waitForSelector('.graph-container svg');

This ensures Puppeteer doesn't "snap the photo" before the calculator has finished drawing the lines.
