1. The Apple Pencil API (PencilKit) & The Eraser Tweak
Apple provides a framework called PencilKit, which is incredibly powerful. It gives you the low-latency drawing canvas (PKCanvasView) and standard tools right out of the box.


If you use Apple’s default UI floating palette (PKToolPicker), you are locked into Apple's default behavior. However, to get the specific behavior you want—where the eraser automatically switches back to the previous writing tool after a stroke—you have to ditch the default tool picker and build your own custom toolbar UI, managing the tools programmatically.


Here is how that workflow breaks down in code:



* You track the active tool state manually (e.g., saving the current PKInkingTool as lastUsedTool).

* When the user selects your custom Eraser button, you change the canvas tool to PKEraserTool.

* You implement the PKCanvasViewDelegate protocol and listen for the canvas to finish processing a stroke via the canvasViewDidEndUsingTool(_:) method.

* Inside that method, if the active tool was the eraser, you immediately programmatically reassign canvasView.tool = lastUsedTool.


It’s completely doable and actually only requires a small amount of logical scaffolding once you control the tool selection state.



2. The Real Challenge: Embedded HTML & Rich Text Layout
This is where the project shifts from "moderately difficult weekend project" to "world-class engineering hurdle."


Notability isn't just a drawing app; it’s a sophisticated hybrid layout engine. It simultaneously handles absolute vector coordinates for handwriting, responsive text wrapping, images, audio sync, and file attachments.


Adding support for embedded HTML and exporting it seamlessly introduces two major friction points:


The Layout Engine Friction
PencilKit drawings exist on a specialized infinite canvas layer. Standard text and HTML elements exist in a web view (WKWebView) or a text rendering engine (TextKit 2). Getting handwritten text to anchor naturally to a block of HTML so that it moves when the HTML content expands or scrolls requires building a custom structural model. You have to map canvas coordinates to specific DOM elements or text layout bounding boxes.


The Export Paradox
When you write in a note-taking app, your vector lines are saved as raw coordinate data (points, pressure, velocity, tilt).



* To export that alongside embedded HTML, you either have to render the handwriting into transparent PNG/SVG overlays that align precisely via CSS over the HTML elements, or

* You have to convert the entire note into an HTML5 <canvas> object where the strokes are redrawn using JavaScript.


Neither option is trivial, and maintaining perfect visual fidelity between the iPad screen and a desktop browser opening that exported HTML is incredibly tough.

## Gemini

If you want to marry Apple Pencil input with dynamic HTML, you actually don't have to code a massive, ground-up note-taking architecture. You just need to build a single structural "sandwich" view using a native iOS wrapper app.


The strategy relies on overlaying a native Apple PencilKit Canvas directly on top of an iOS Web View (WKWebView).


The concept can be broken down into two distinct approaches depending on how the layers interact: the Static/Stacked Layer approach (easier) and the Dynamic Injection approach (harder but much cleaner).



Approach 1: The Stacked Layer Approach (The "Sandwich")
In this architecture, your LLM-generated HTML runs inside a standard WKWebView. Directly on top of that web view sits a transparent PKCanvasView (PencilKit).


The primary hurdle here is gesture conflict: If you touch the screen, how does the iPad know whether you want to draw a line or tap an interactive button in your HTML code?


You solve this elegantly by overriding the native hitTest method in Swift based on the input type.


class TouchPassThroughCanvas: PKCanvasView {
    override func hitTest(_ point: CGPoint, with event: UIEvent?) -> UIView? {
        // Look at the incoming touch event
        if let touches = event?.allTouches, let touch = touches.first {
            // IF the user is using the Apple Pencil, lock interaction to the drawing canvas
            if touch.type == .pencil {
                return self
            }
        }
        // IF it's a finger tap or scroll, pass it straight through to the HTML layer below
        return nil 
    }
}

The Pros & Cons

* Pros: Highly stable. Your handwriting layer utilizes Apple's ultra-low latency sub-millisecond drawing pipelines. Your interactive HTML diagram executes raw JavaScript without stuttering.

* Cons: The handwriting exists on an independent overhead pane. If your HTML contains an animated element that moves across the screen, or a scrollable container, your hand-drawn annotations will stay exactly where you drew them, losing synchronization with the background content.



Approach 2: The Web-Native Approach (Converting Ink to SVG)
If you need your sketches to anchor perfectly inside the HTML content itself, you have to bypass the stacked transparent canvas concept entirely. Instead, you capture the pencil strokes using an invisible tracking view, serialize the raw data, and inject it straight into the webpage's DOM.


PencilKit provides deep structural access via PKDrawing and PKStroke. Every time your pen leaves the screen, you can capture the path data and output it as a text string.


The Pipeline Architecture

* Draw: The user draws a stroke using a temporary PencilKit overlay.

* Serialize: The canvasViewDidEndUsingTool delegate fires. You take canvasView.drawing and convert the mathematical path points into an optimized vector <path> string.

* Bridge: You send that path string across Apple’s native JavaScript bridge using evaluateJavaScript().

* Render: A script inside your HTML app receives the coordinates and instantly appends a new path element into an embedded inline <svg> element or paints it onto an HTML5 <canvas> element.


// Swift Code monitoring the canvas
func canvasViewDrawingDidChange(_ canvasView: PKCanvasView) {
    // 1. Convert PencilKit drawing to an SVG string format
    let bounds = canvasView.drawing.bounds
    if let svgData = try? canvasView.drawing.image(from: bounds, scale: 1.0) {
        // 2. Pass the graphic asset or raw vector strings into the webpage context
        let jsCode = "insertHandwritingLayer('\(svgData.base64EncodedString())')"
        webView.evaluateJavaScript(jsCode, completionHandler: nil)
    }
}


Summary of Feasibility
If you want to tinker with this via a basic template app, the first approach (Stacked Layer) can be fully implemented in under 50 lines of Swift code. It allows you to point a web container to your interactive HTML layouts while leaving PencilKit permanently enabled for on-the-fly annotations right over top of the interface.
