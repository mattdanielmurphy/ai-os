## Gemini

The reason you can't pass a custom model name like deepseek directly into Claude Code (e.g., running claude --model deepseek or using /model deepseek) is due to client-side validation.


Claude Code strictly validates model strings before it ever sends a network request. It requires the model identifier to be a recognized internal alias (like sonnet, opus, haiku, fable), match an active organization allowlist, or start explicitly with the claude- prefix. If you pass an unrecognized string, Claude Code rejects it immediately.


To successfully route Claude Code through LiteLLM to an external model like DeepSeek or Gemini, you have to trick the CLI into thinking it is talking to Claude.



How to Fix Your Setup
Instead of passing deepseek to Claude Code, you must tell Claude Code to use a standard Claude model name, and then let LiteLLM intercept and remap that name to your desired model.


1. Update your LiteLLM Configuration
LiteLLM wildcards (*) can sometimes cause routing issues depending on the exact string Claude Code sends. It is safer to map the explicit model strings that Claude Code utilizes:


model_list:
  # Route what Claude Code thinks is Sonnet to DeepSeek V4 Pro
  - model_name: claude-sonnet-4.5
    litellm_params:
      model: openrouter/deepseek/deepseek-v4-pro
      max_tokens: 8192

  # Route what Claude Code thinks is Haiku to DeepSeek V4 Flash
  - model_name: claude-haiku-4.5
    litellm_params:
      model: openrouter/deepseek/deepseek-v4-flash
      max_tokens: 8192

2. Configure Claude Code's Environment Variables
Claude Code uses a primary model for writing code and a secondary small/fast model for background tasks (like generating terminal titles or summaries). You need to point both to your LiteLLM gateway using environment variables in your shell profile (~/.zshrc or ~/.bashrc):


# Point Claude Code to your local LiteLLM proxy
export ANTHROPIC_BASE_URL="http://localhost:4000"
export ANTHROPIC_AUTH_TOKEN="your-litellm-key-if-required"

# Use the fake Claude names that match your LiteLLM config mapping
export ANTHROPIC_MODEL="claude-sonnet-4.5"
export ANTHROPIC_SMALL_FAST_MODEL="claude-haiku-4.5"


Note: Make sure litellm_settings.drop_params: true remains in your LiteLLM config. Claude Code sends Anthropic-specific parameters that will crash non-Anthropic endpoints if they aren't stripped out by the proxy.



Once you restart your terminal and run claude, it will initiate a session believing it is using Sonnet, while LiteLLM silently handles the translation to DeepSeek behind the scenes.
