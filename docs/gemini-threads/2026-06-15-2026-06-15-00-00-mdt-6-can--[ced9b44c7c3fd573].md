## Gemini

Yes, you can automatically forward messages using the Shortcuts app, but there is a major catch regarding automation triggers that you need to know.


While you can create a shortcut that handles the forwarding action, Apple places strict security restrictions on what can run completely in the background without your manual approval.


Here is how the behavior breaks down for the two main types of messaging:



1. SMS and iMessage (Messages App)
You can set up an automation triggered by receiving a message, but it cannot run automatically without interaction.



* The Trigger: Shortcuts allows you to choose "Message" as a trigger (e.g., when I get a message from a specific contact or containing a certain keyword).

* The Catch: Apple disables the "Run Immediately" option for Message triggers.

* The Reality: When the message arrives, you will receive a notification on your iPhone or Apple Watch asking you to tap "Run." Only after you tap it will the message forward. It is a semi-automation, not a passive background task.


How to set it up anyway:

* Open Shortcuts and go to the Automation tab.

* Tap the + (plus sign) to create a new automation.

* Select Message.

* Configure your sender or keyword filters, then select Run After Confirmation (the only option available here) and hit Next.

* Add the Send Message action.

* Map the input shortcut text to your recipient.



2. Email (Mail App)
If you are trying to forward emails, the outcome depends on the trigger you choose:



* Triggered by "When I Open Mail": You can set an automation to forward specific emails when the Mail app opens. This can run immediately without asking, but it requires you to physically open the app to kick off the process.

* Triggered by "When Email Arrives": Similar to iMessage, if you set the trigger to fire the moment an email lands in your inbox, iOS forces a "Run After Confirmation" restriction. You will still have to tap a notification to send it.



The Better Alternative for Pure Automation
If you need a zero-interaction, fully automated background forwarder, avoiding the Shortcuts app entirely is usually the best path:



* For Email: Set up server-side rules directly inside your email provider (Cloud iCloud, Gmail, Outlook, etc.). These process instantly on the server the moment an email hits your account, requiring no device interaction or notifications.

* For SMS: If you need to forward SMS text messages completely automatically to another device without tapping a prompt, iOS natively supports Text Message Forwarding, though it only works if you are forwarding to another Apple device signed into your Apple ID (like an iPad or Mac). You can find this in Settings > Messages > Text Message Forwarding.

No, you do not need to create an API key to use this webhook.


In Make, adding an API key here is entirely optional. It is used to restrict who can send data to your webhook.


Here is how to decide whether to add one:



* Leave it blank (Recommended for simplicity): If you just want to test the connection or if the service sending data to Make doesn't support custom HTTP headers, leave the API keys section empty and click Save. Anyone with the final webhook URL will be able to send data to it.

* Add an API key (For extra security): If you want to ensure that only your specific external application can trigger this webhook, you can add a key. However, you will then have to configure your external application to pass that exact key in the HTTP header as x-make-apikey.


If you are just setting this up for a standard integration, you can safely skip the API key step, click the purple Save button, and Make will generate your unique webhook URL.
