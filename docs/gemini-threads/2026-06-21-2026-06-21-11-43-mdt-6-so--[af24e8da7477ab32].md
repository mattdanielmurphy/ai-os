Implementing the Bridge Tool in Mastra
You can wrap your persistent node-pty session inside a Mastra tool definition. This lets your high-level orchestrator cleanly hand over tasks to your subscription-backed CLI without restarting the process every turn.


Here is how that tool implementation looks in your TypeScript server:


import { createTool } from '@mastra/core/tool';
import { z } from 'zod';
import { ptySession } from './pty-manager'; // Your existing Warm PTY multiplexer module

const executeSubscriptionTask = createTool({
  id: 'execute_subscription_task',
  description: 'Executes heavy development work using the flat-rate subscription CLI line out-of-band.',
  inputSchema: z.object({
    taskInstruction: z.string().describe('The complete refactoring or generation command text'),
  }),
  execute: async ({ context }) => {
    return new Promise((resolve, reject) => {
      let outputBuffer = '';

      // 1. Listen to the stdout stream from your warm PTY session
      const dataHandler = (data: string) => {
        outputBuffer += data;
        
        // Match your existing project rules for runaway log slicing
        if (outputBuffer.length > 10000) { // 10KB cap protection
           ptySession.write('\x03'); // Send SIGINT Ctrl+C to kill the active run
        }
        
        // Detect when the CLI finishes its task loop
        if (data.includes('Task Completed') || data.includes('agy-prompt-ready')) {
          ptySession.offData(dataHandler);
          resolve({ status: 'success', rawOutput: outputBuffer.slice(0, 5000) });
        }
      };

      ptySession.onData(dataHandler);

      // 2. Inject the instruction into the active subscription line via stdin
      ptySession.write(`${context.taskInstruction}\n`);
      
      // Enforce your project's absolute 15-second hardware watchdog timeout
      setTimeout(() => {
        ptySession.offData(dataHandler);
        ptySession.write('\x03'); // Force kill
        resolve({ status: 'timeout', rawOutput: outputBuffer.slice(0, 2000) });
      }, 15000);
    });
  },
});


The Workflow Advantages
Using node-pty to control the CLI as a background child process gives you three massive advantages over using the standard IDE interface:



* Total Telemetry Control: Because you are streaming the raw terminal chunks (onData) into your own Node.js script, you can print every single line out to a separate macOS terminal running tail -f. You see exactly what thoughts the CLI is parsing in real time.

* Perfect Stream Slicing: If the CLI gets stuck in an infinite build loop or dumps a massive 5,000-line error cascade, your script can instantly clip the buffer or issue a text-based Ctrl+C interrupt right into the stream. The client never gets bloated, and your historical token cache stays clean.

* Seamless File Synchronization: When the background agy CLI updates files on your Mac, those changes immediately hit the disk. Since the IDE is looking at the same directory structure, it instantly catches the update and draws the clean visual git diff lines across your text screen.


You keep the flat-rate subscription savings, gain absolute data visibility, and completely protect your environment from unmanaged client slurping.
