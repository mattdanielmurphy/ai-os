[2026-06-29 09:47 MDT-6] is it possible for antigravity-cli to keep track of how many tokens it's used?

---

## Gemini

Yes, it is possible. Because Antigravity CLI operates as a Terminal User Interface (TUI), it includes native slash commands to monitor your token consumption and overall quota directly from your terminal session.


You can track your usage using two specific commands:



* /context: This displays a breakdown of the token usage for your current session, categorized by input, output, and context-window checkpoints. It is incredibly helpful for monitoring how much data your subagents and file edits are actively consuming.

* /usage: This shows your broader quota and rate-limit status across all available models (like Gemini or Claude) under your plan, giving you a clear view of how much of your capacity remains before hitting any time-window limits.


If you want to view your exact, real-time remaining capacity or manage your account-level token budget details, you can also view your current limit status on the Usage Limits page found within your Settings.

## Gemini

The native agy CLI doesn't have a configuration toggle to automatically output token stats at the end of every individual turn. It sticks to the explicit /context and /usage slash commands to keep the terminal output clean.


However, you can get exactly what you're looking for by using one of these two workflows:


Option 1: Use the Antigravity Token Monitor Extension
If you are running your terminal/CLI sessions inside VS Code or a compatible editor, there is a community-built extension called Antigravity Token Monitor.



* It reads local runtime metadata and .pb log files on your machine to track turn-level token additions in real time.

* While it's primarily a sidebar tool, it includes a standalone CLI utility (bun run dev scan --current) that isolates the current turn delta from the session total.


Option 2: Wrap the agy execution in a custom script
If you want a pure terminal solution without typing /context after every prompt, you can launch a wrapper shell script or write a lightweight terminal hook. Because the CLI saves its active session metadata locally to your home directory (under ~/.gemini/antigravity/ or your system's global app state), you can monitor the file size growth or parse the runtime log signals to automatically echo the turn's token delta right after the process returns control to the shell.

---

## Gemini

Extensions like Antigravity Cockpit, Cockpit Tools, and Antigravity Panel aren't fetching your quota from a public external Google API. Instead, they intercept and parse metrics exposed directly by your local Antigravity environment.


Here is exactly how they extract that data under the hood:


1. Process & Language Server Interception
Antigravity runs a background Language Server Protocol (LSP) process to handle its agentic workflows. Extensions look for this specific active process via system tools (like wmic on Windows or native Unix commands on macOS/Linux). Once found, they scrape:



* The local port the server is broadcasting on.

* The session authentication token used by the IDE to talk to Google's backend.


2. Querying Local Internal Endpoints
Once an extension has the port and auth token, it periodically polls the local language server's internal telemetry endpoints. Because the IDE constantly streams remaining quota information down to keep its own internal meters accurate, the extension can catch this raw payload, parse the JSON, and map out the remaining percentages and reset countdowns for individual model pools (Gemini, Claude, GPT-OSS).


3. Scraping Local SQLite Databases (state.vscdb)
For multi-account tracking and history mapping, Cockpit Tools reads directly from the IDE's local workspace storage. Antigravity caches user states, account indexes, and active session limits locally in a SQLite database file called state.vscdb within your current directory or global app data folders. The extension hooks into this database to:



* Identify which account is active.

* Pull cached quota snapshots if a live network response stalls.

* Trigger automated account switching if your current account dips below a configured threshold.



⚠️ Note: Because this entirely depends on internal, undocumented metrics exposed by the local application, updates to Antigravity's underlying language server architecture or changes to how tokens are stored can temporarily break the data pipeline until the extension maintainers push a fix.
